# 业务验收与发行核对

## 用例与证据

以 [PRD 验收表](requirements/04-验收与运营-prd.md) 的编号作为索引。回归使用虚构身份和独立的 MySQL 测试库，对照 API、业务状态、持久化事件及文件输出。

| 编号 | 核对项 | 可复现证据 |
| --- | --- | --- |
| AC-01 | 1 个空岗与 2 个录用接受请求 | 事务回归用独立连接并发，只有 1 个成功，另一条返回编制不足。 |
| AC-02 | 追溯撤岗时展示仍有效的任职 | HTTP 回归读取撤岗冲突的任职编号和起始日，事务回归同时检查占编记录。 |
| AC-03 | 一人两份申请与独立评估 | 事务回归核对同一候选身份、不同申请编号和逐申请评价。 |
| AC-04 | 撤销录用释放编制 | 事务回归核对已释放占用、撤销决定与可重试的候选人。 |
| AC-05 | 4 月 16 日调岗 | HTTP 回归逐日读取 15 日和 16 日的部门、岗位和任职段截止日，核对受影响班次、成本期间、权限和原回执重放。 |
| AC-06 | 生效日冲突 | HTTP 回归检查版本与冲突区间，浏览器工作台展示原因。 |
| AC-07 | 跨午夜归属 | HTTP 回归验证只出现于起始工作日，核对每个打卡回执和 480 分钟。批次验证所选失败行、被拒原因、原键重放和未选行尝试次数。 |
| AC-08 | 两个请求争用最后一天假期 | 事务回归并发预占同一额度，核对唯一成功记录、账本及余额。 |
| AC-09 | 9,000 元按两段各 15 天分摊 | HTTP 回归、公开演示与员工工资单同时读取两条各 4,500 元的分段。 |
| AC-10 | 缺考勤阻断送审和封账 | HTTP 回归与公开演示先试算，确认阻断原因，补齐考勤确认后通过。复核回归再核对代办撤销、版本冲突和实际处理人与委托人。 |
| AC-11 | 原单 9,000 元，原期复算 9,300 元，下期补差 300 元 | HTTP 回归核对原单、原部门、唯一补差及原封账摘要，公开演示核对含当期工资的补差单。 |
| AC-12 | 响应丢失及同一调薪决定重放 | HTTP 回归发完请求后关闭连接，先从独立复核会话观察持久行，再使用原请求键及新请求键重放。 |
| AC-13 | 法人和集团成本对账 | 从两个部门成本、集团按币种总额及 CSV 逐层回读，对照封账摘要。 |
| AC-14 | 非薪资权限主管越权查询 | HTTP 回归尝试明细、员工入口和附件，均返回 404。隔离集团的成本查询和集团 CSV 无数据。 |
| AC-15 | 办结后前任主管按原授权范围回读 | HTTP 回归核对前任主管、后续主管的日期范围，员工仍可领取本人归档单据。 |
| AC-16 | 未交回设备阻止办结 | HTTP 回归完成其他清单后再办结，返回唯一的设备责任项；归还确认后可办结。 |

绩效验收同时覆盖周期待办、加权评分、自评冻结、独立 HR 校准、定稿可见性、主管交接与追加修订。

2026 年 11 月 26 日在 PHP 8.2.30、MySQL 8.4.13 的空库中复跑以上 16 条用例。Chrome 158 无头会话从工作台实际完成三条场景，分别是按任职历史回查调岗影响、只重试所选假勤行、由指定代办人封账并查阅两名操作者。

## 重跑

在独立 MySQL 8.4 库设置应用配置，测试库名称以 hcm_test_ 开头。从仓库根目录启动 PHP HTTP 入口后，在另一个终端运行以下命令。

```sh
python3 tests/http_smoke.py http://127.0.0.1:8080
php tests/recruitment.php
php -d memory_limit=256M tests/payroll_capacity.php 1000
```

公开演示的运行和恢复步骤见 [演示](demo.md) 与 [恢复操作](backup-and-restore.md)。容量记录包括测试环境、准备时间、热身与三次正式试算。本次合成场景中，1,000 人试算三轮最慢 3.0957 秒，目标上限为 300 秒。[容量实测记录](payroll-capacity.md)

## 升级回读

2026 年 11 月 26 日从公开标签 v1.0.0 安装 14 项迁移并走完演示，再执行 v1.1.0 的迁移 015。升级前后分别回读两期工资单、部门分摊、补差行和 SHA-256 封账摘要，结果逐项相同。同一环境还用 v1.1.0 从空库走完整演示，重复完成、回读及 MySQL 备份恢复的结果一致。[升级原始回读](upgrade-result.json)

2026 年 11 月 25 日在 Windows、PHP 8.2.30 和 MySQL 8.4.13 中，从开发快照 7d28b0f 的空库执行迁移 001 至 011，并通过旧版 HTTP 接口走完发布。切换到当前代码后，同一数据库只应用 012 绩效、013 员工自助和 014 离职迁移。

用有相同授权的独立复核人与员工会话，在升级前后分别读取两期单据。4 月 9,000 元、两部门原始分段、5 月原法人单独发放的 300 元补差、唯一补差行与两期 SHA-256 摘要均一致。组合场景在 5 月前已跨法人调出，公开演示则保留 5 月原法人在职和正常工资。

## 已知边界

- 演示采用基础工资、固定津贴、按时扣减及简化扣缴参数。部署方需要提供和核准本地规则及来源数据。
- 考勤接入使用可逐行重试的班表与打卡批次。用合成打卡验证了重放和回执，在对接设备时需验证设备的具体格式、时区与事件标识。
- 默认会话存储为 PHP 文件。多实例部署需要可共享的会话存储。
- 首个公开发行从本仓库的稳定标签开始。发行之前的开发快照可用于内部升级回读与验证历史单据。
