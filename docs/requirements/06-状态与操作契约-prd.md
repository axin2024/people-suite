# 集团人力资源管理系统 HCM｜状态与操作契约

## 工资批次的生命周期

草案→试算→待复核→封账→员工发布。封账后走追溯决定和新批次补差，不能覆盖原单。

## 权限与操作者

招聘限本岗，集团人事管理任职，经理仅看直属考勤与目标，薪酬制单与复核分权，员工仅查本人。 在待审批与已完成状态分别检查读写范围，委托与代办保留真实操作者身份。

## 两个关键交互

1. 提交调岗须含组织、员工、生效日、原任职版本；返回分段区间和受影响的排班、费用期间。
2. 试算输入期间、工资规则与考勤水位，返回员工逐项来源、缺数、舍入及总额；复核人与制单人分离。

## 业务操作与异常回执

| 操作域 | 在当前数据上的处理 | 冲突、拒绝或降级行为 |
|---|---|---|
| 组织与编制 | 调入和招录共用名额，已占编制与预算期一致；组织调整保留旧任职关系。 | 追溯撤岗先提示所有有效任职。 |
| 招聘与录用 | 候选人可应聘多岗，招聘团队只见分配岗位；接受录用并校验名额后转入职。 | 撤销录用释放编制并留决策记录。 |
| 任职与合同 | 有效任职区间按日切分，主岗不重叠；合同是独立版本；跨法人调动记录转出与接收。 | 冲突生效日提示冲突区间。 |
| 排班与假勤 | 跨午夜班次归属班表工作日；审批锁定请假余额，销假或拒批恢复可用额度。 | 并发申请最后一天年假不能重复扣减。 |
| 薪资计算 | 使用任职、假勤和薪资快照，薪酬员可解释每一项来源；当地扣缴参数由部署方配置。 | 缺考勤数据提示阻断行，不能封账。 |
| 封账与补差 | 封账后工资单不可直接重写；历史追溯产生本期补差项，保留原算、重算及差额。 | 同一调薪决定重放两次仅有一项补差。 |
| 绩效与成本 | 绩效记录按周期和可见人收集，定稿后保留修订；按生效任职段汇总费用。 | 跨部门经理无权查看个人工资明细。 |
| 员工服务与离职 | 员工只查本人资料，离职办理冻结新增申请并结清待办，人事复核后撤销业务身份。 | 未交回设备时显示责任清单并阻止完结。 |

## 失联、中断及恢复

任职生效区间按员工串行校验，薪资封账冻结规则和输入；补差按原工资行与决定编号唯一，考勤回执按设备与事件唯一。 中断后先查询最后一个已持久的业务标记，再决定安全重试、补偿或人工复核。对外回执携带对象身份及业务版本。批量操作允许逐项查看成功、失败和未开始。

## 发布级业务断言

期中离职冻结新权限但保留本人获授权的历史单据领取途径；公开教程只使用合成身份。 原工资单 9000、原成本 4500＋4500 保留，下期单列补差 300，归属原上半月部门并关联决定编号。
