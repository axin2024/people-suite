# 薪资试算容量验收

## 样本和口径

2026 年 11 月 26 日，在 Windows 运行单个 PHP 8.2.30 进程。PHP 内存上限 256 MiB。独立的 MySQL 8.4.13 通过本机回环连接，InnoDB 缓冲池为 128 MiB，连接上限为 151。

一个法人、两个部门、一个 30 天账期，1,000 名合成员工于 4 月 16 日从运营转到财务。每人月薪 9,000 元，20 个各 8 小时的已核对班次。招聘、签核、入职、调动和考勤确认经业务服务执行。测试脚本直接生成 20,000 个合成班次及其 40,000 条状态版本。

同一账期先热身一次，再依次执行三次完整试算。每次计量读取快照、计算并写入工资单和分段结果。合成数据准备、独立复核封账及摘要校验单独计时。这个场景测量本机单账期串行运行。

## 结果

| 指标 | 实测 |
| --- | ---: |
| 数据准备及考勤确认 | 92.7293 秒 |
| 热身试算 | 2.8077 秒 |
| 第 1 次试算 | 2.8828 秒 |
| 第 2 次试算 | 2.6916 秒 |
| 第 3 次试算 | 3.0957 秒 |
| 送审、封账及摘要校验 | 0.0895 秒 |
| 三轮 PHP 峰值已分配内存 | 4 MiB |
| 工资单与阻断人数 | 1,000 张，0 人阻断 |
| 总应发、实付及总成本 | 各 9,000,000.00 元 |
| 每部门成本 | 各 4,500,000.00 元，各 1,000 个分段 |

三轮均通过 300 秒容量目标。试算脚本逐轮核对人数和金额，随后校验封账摘要、总成本及各部门分段。

## 复现

按[配置参考](configuration.md)连接独立的 `hcm_test_*` 测试库，执行以下命令。每次运行会在库内创建一个独立的合成集团。

```sh
php -d memory_limit=256M tests/payroll_capacity.php 1000
```

终端输出 JSON，包括负载大小、环境参数、单轮时间及各轮 PHP 峰值。[本次原始计量](payroll-capacity-result.json)
