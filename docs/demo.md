# 工资分段与追溯补差演示

样例从一个虚构员工的入职开始。月中换岗后，原工资单保留两个任职分段。下一期补差归属原费用部门。可以分别通过工作台、员工工资单和 CSV 核对这些记录。

## 建立演示库

在 MySQL 8.4 新建专用数据库，例如 hcm_demo_north，字符集为 utf8mb4。为这个库创建应用账号，设置 HCM_DSN、HCM_DB_USER 和 HCM_DB_PASSWORD，再运行迁移。样例命令仅接受 hcm_demo_ 开头的数据库。一个演示库内使用 north-demo 集团。

```sh
php bin/hcm.php migrate
php bin/hcm.php demo-seed
```

执行 demo-seed 后，从标准输入输入自行设置的 12 至 72 字节演示口令并按回车。五个虚构账户使用同一个演示口令。命令返回集团代码、账号、账期和批次编号。准备一个新的演示库即可重置，保留已有库供对照。

在终端隐藏输入时，可在 Bash 中运行 `read -r -s HCM_DEMO_INPUT`，输入后执行 `printf '%s\n' "$HCM_DEMO_INPUT" | php bin/hcm.php demo-seed`。结束后运行 `unset HCM_DEMO_INPUT`。

| 账号 | 职责 |
| --- | --- |
| hr@example.test | 集团管理员和 HR，核对任职与考勤确认。 |
| manager@example.test | 班次核对和直属员工记录。 |
| maker@example.test | 试算、补差与送审。 |
| reviewer@example.test | 独立复核、封账、发布与成本核对。 |
| employee@example.test | 本人考勤和已发布工资单。 |

演示规则按人民币分记账，津贴、缺勤扣款与扣缴参数均设为零。正式使用时，由部署者核准各地区参数。合成打卡设备标识为 DEMO-GATE。

## 在浏览器中走完流程

按 README 的本地回环方式启动工作台。每个角色使用独立浏览器会话，集团代码填 north-demo。

1. 用 HR 登录，在「任职档案」找到 DEMO-001。查询 2026-04-15 与 2026-04-16，可以分别看到运营组和财务组。打开「假勤导入」核对 3 行班表与 6 行合成设备回执。4 月 30 日夜班于 5 月 1 日结束，归属 4 月 30 日。
2. 用制单人打开「薪资账期」的 2026-04，选择 DEMO-30 试算。当前任职有一条阻断工资单，原因是缺少期间考勤确认。此时无法送审。
3. 用主管打开「排班与假勤」，分别确认 4 月 10 日、4 月 30 日和 5 月 12 日出勤，填写不同决定编号。用 HR 在任职的「考勤期间确认」分别确认 4 月和 5 月。4 月区间为 [2026-04-01, 2026-05-01)，预期 2 班。5 月区间为 [2026-05-01, 2026-06-01)，预期 1 班。
4. 制单人用最新水位重新试算并送审 4 月。用复核人核对 9,000 元工资、运营组和财务组各 4,500 元，随后封账、核验 SHA-256 摘要并发布。记下员工工资单编号。
5. 制单人在 5 月「追溯补差」填写 4 月工资单编号、原分段行号 1、更正后月工资 960000 分、上一笔补差编号 0、决定编号 APRIL-RATE-CORRECTION，并填入说明。使用相同说明和决定编号再登记一次，核对只返回同一补差编号。
6. 用 5 月规则 DEMO-ACTUAL 试算并送审，由复核人封账发布。5 月正常工资 9,000 元归财务组，300 元补差单列在原运营组，实付 9,300 元。员工在「我的工资单」可查看并下载两期记录。

## 自动完成和回读

从刚初始化的演示库运行以下命令，可以自动完成同一案例。每条命令从标准输入读取同一个演示口令。

```sh
php bin/hcm.php demo-finish
php bin/hcm.php demo-check
```

demo-finish 会处理缺少考勤确认的试算、已导入班次、独立复核和补差重放。使用相同输入重复执行时，已经完成的处理返回已有回执。需要手动操作时保留 demo-seed 生成的待核对班次，完成后运行 demo-check。

demo-check 从已发布工资单、历史任职分段、两个账期的封账摘要及部门成本回读。输出金额使用分，保留账期编号、工资单编号与 SHA-256。预期关键字段如下。

| 记录 | 预期 |
| --- | --- |
| 4 月原工资单 | 900000 分。450000 分归 OPS，450000 分归 FIN。 |
| 5 月正常工资与实付 | 正常工资 900000 分，计入补差后实付 930000 分。 |
| 追溯补差 | 唯一一行 30000 分，归 OPS，关联 APRIL-RATE-CORRECTION 和原工资单第 1 行。 |
| 封账 | 两个月份均能用持久化记录重新生成原摘要。 |

2026 年 11 月 25 日在 Windows、PHP 8.2.30 与 MySQL 8.4.13 中从空库运行样例。首次自动完成、重复执行、单独回读以及 SQL 导出后恢复至独立新库的回读结果一致。源库与恢复库的工资单编号、原部门分段、唯一补差及两个封账摘要均一致，恢复库健康探针返回就绪。这里的摘要包含本次运行记录，重新创建样例时以当次封账回执为准。
